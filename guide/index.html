Using IRIS on Katana

The steps every imaging workflow shares: getting a dataset into your Katana scratch before your first run, and viewing and comparing runs once they finish. Each workflow's own page covers launching it.

Staging a dataset

Do this once per dataset. Every run reads the dataset from your scratch and writes its run directory back into it.

Lay out the folder

A dataset is one folder holding one volume and its training pairs, laid out like this on your own computer:

my-dataset/ volume/ every .nc file of one volume, read in file-name order train/ images/ 2D TIFF slices of the volume, at its bit depth labels/ the same file names; 0 = unlabelled, then 1, 2, 3... per class
  • Label your training slices in Dragonfly or any other tool. Pixels left at 0 are ignored, so you can label just part of a slice.
  • Each label slice has the same file name and size as its image. Labels can be any whole-number type; the number of classes is read from them.
  • IRIS adds a runs/ folder the first time you run on the dataset, with one folder per run.

Copy it to your scratch

Copy through Katana's data mover, kdm.restech.unsw.edu.au, never a login node. From a terminal on your computer, replacing zID with yours:

rsync -av --progress my-dataset/ zID@kdm.restech.unsw.edu.au:/srv/scratch/zID/my-dataset/

On Windows, use WinSCP to the same host and folder, logging in with your zID. To add or replace a few training pairs later, the OnDemand Files app is fine; copy volumes through the data mover.

The dataset can go anywhere under /srv/scratch/zID, so you can keep several datasets your own way. Your scratch holds 128 GB: about seven 16 GB volumes, before any run directories. Scratch has no backup, so keep your own copy of the original data.

Viewing and comparing runs

Find the job output

When a job ends, PBS writes its output into your dataset as runs/<job ID>.OU, beside the run directory, runs/<job number>/. When the job succeeds, its output ends with two lines to paste, one starting with the full path of iris-view and one of iris-compare. Read it in a terminal in the Virtual Desktop below, for example with tail /srv/scratch/zID/my-dataset/runs/1234567*.OU.

Start a Virtual Desktop

In Katana OnDemand, start a Virtual Desktop with no GPU, 4 cores, 16 GB of memory and 4 hours. That is enough for a 16 GB volume, and asking for more only queues you longer. One desktop serves everything below. Open a terminal in it.

View a run: iris-view

Paste the iris-view line from the job output. napari opens with your volume and the run's label volume over it at half opacity. Scroll through the slices with the slider under the image. Only the slices you look at are read, so a 16 GB volume fits in the desktop. Close the napari window to quit.

Run iris-view with no run directory to list your 10 most recent finished runs, then type the number beside the one to open.

Compare runs: iris-compare

Paste the iris-compare line. It adds your new runs to your tracking store, /srv/scratch/zID/iris/tracking.db, then opens MLflow in Firefox inside the desktop. On the left, switch from GenAI to Model Training, then click Runs: each run is named after its job ID, under its experiment. Select runs and click Compare to see their settings and per-class Dice and IoU side by side. Leave the terminal open while you use MLflow; Ctrl+C there stops it.

Your tracking store is created the first time you run iris-compare. If it is ever lost, iris-rebuild, in the same folder as iris-view, rebuilds it from your run directories.

Open the label volume in Fiji

  1. In the desktop's terminal, run module load fiji/20240614-2117, then start Fiji with ImageJ-linux64.
  2. Choose File › Import › Bio-Formats, and pick labels.tif in the run directory. In the options, set View stack with to Hyperstack and tick Use virtual stack. Slices are read as you scroll, so stepping through them is slow but works.
  3. The image opens black: classes 1, 2, 3 sit at the bottom of a 0–255 grey scale. Choose Image › Adjust › Brightness/Contrast…, click Set and set the maximum to your number of classes. It stays set as you scroll.

To look around the labels over your volume, iris-view is quicker. Use Fiji to cut out a region for ParaView.

A region in 3D with ParaView

A whole label volume is too large to render in 3D in the desktop: a 16 GB volume's labels take 8 GB once read. Crop a region in Fiji first.

  1. Import labels.tif with Bio-Formats as above, this time with Use virtual stack unticked and Specify range for each series ticked. Set the T range to the slices you want, such as 600–800: Bio-Formats lists the slices as time points. Only those slices are read.
  2. Draw a rectangle around the region, then choose Image › Crop.
  3. Choose File › Save As › Tiff…, and save it as crop.tif in the run directory. Fiji offers your home folder first. A 200 × 500 × 500 crop is 50 MB.
  4. Close Fiji and anything else you have open: ParaView can hang while Fiji is still running. In a new terminal, run module load paraview/6.0.0, then paraview.
  5. Choose File › Open and pick crop.tif. ParaView asks which reader to use: choose TIFF Series Reader, not GDAL Raster Reader.
  6. In the Properties panel, tick Use Custom Data Spacing and enter the voxel size in the run's dataset.json in all three Custom Data Spacing boxes, so the region isn't squashed. Click Apply. Nothing shows until you do, and then only the region's outline.
  7. To show the boundary between two classes, choose Filters › Common › Contour. It starts with one value, halfway through the labels in your region; set it halfway between the two classes, such as 2.5 between classes 2 and 3, and click Apply.
  8. Or select crop.tif in the Pipeline Browser and set its Representation to Volume. Dragging to rotate stays smooth; after you let go, ParaView takes a few seconds to redraw at full detail.

Copy a run directory home

Use the same rsync with its source and destination swapped, run from your computer. For example, one run directory:

rsync -av --progress zID@kdm.restech.unsw.edu.au:/srv/scratch/zID/my-dataset/runs/1234567/ my-dataset/runs/1234567/

Or use WinSCP to the same host and folder.
