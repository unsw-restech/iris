Using IRIS on Katana

The steps every imaging workflow shares: getting a dataset into your Katana scratch before your first run, and viewing and comparing runs once they finish. Each workflow's own page covers launching it.

On this page

  2. Send it to Katana

  4. View and compare runs
  5. Fiji and ParaView

Step 1 · Before your first run

Prepare your dataset

Do this once per dataset. Every run reads the dataset from your scratch and writes its run directory back into it.

Lay out the folder

A dataset is one folder holding one volume and its training pairs, laid out like this on your own computer:

my-dataset/ volume/ every .nc file of one volume, read in file-name order train/ images/ 2D TIFF slices of the volume, at its bit depth labels/ the same file names; 0 = unlabelled, then 1, 2, 3... per class
  • Label your training slices in Dragonfly or any other tool. Pixels left at 0 are ignored, so you can label just part of a slice.
  • Each label slice has the same file name and size as its image. Labels can be any whole-number type; the number of classes is read from them.
  • IRIS adds a runs/ folder the first time you run on the dataset, with one folder per run.

Where it goes

The dataset can go anywhere under /srv/scratch/zID, so you can keep several datasets your own way. Your scratch holds 128 GB, shared between your datasets and their run directories. Scratch has no backup, so keep your own copy of the original data.

Step 2 · Before your first run

Send it to Katana

What is Globus

Globus copies your dataset folder to Katana. It was made by the University of Chicago and the US Department of Energy's Argonne National Laboratory to transfer research data securely. You use it from a web page, signing in with your zID. You choose a folder on your computer and a folder on Katana and press Start, and Globus copies the files in the background: you can close the browser, and if your computer sleeps it picks up where it left off. It checks that every file arrived intact, and handles datasets of any size.

Install Globus Connect Personal once

Globus Connect Personal is software you install on a computer so Globus can transfer files between it and other Globus endpoints. Katana has an endpoint too, so once your computer is one, Globus can copy between them.

  1. Download Globus Connect Personal for your computer.
  2. Follow the instructions to install it.
  3. Open Globus Connect Personal and follow the instructions to enter your UNSW credentials.
  4. Give your computer a name you'll recognise, such as My laptop, and click Save.

Send your dataset folder

Send your dataset folder

Globus opens with your Katana scratch on one side. On the other side, choose your computer by the name you gave it, select your dataset folder, and press Start. New to Globus? Its transfer tutorial walks through the file manager step by step.

Already in Katana OnDemand? Click Files in the top menu, open your scratch folder, and click Open in Globus.

To add or replace a few training pairs later, copy them in under Files in the top menu of Katana OnDemand. Files suits a few training pairs only; send volumes with Globus.

Make it repeat (instrument PCs)

Optional. If an instrument PC keeps producing volumes, Globus can send new ones to your scratch on a schedule. Before pressing Start, open Transfer & Timer Options, choose to sync so only new or changed files are copied, and set how often it repeats.

  • If Globus emails you that your repeat is paused, sign in to Globus and press Resume. It pauses when it needs you to sign in again.
  • A repeat that fills your 128 GB scratch makes later runs fail. Watch how much it copies.

In a terminal instead

Copy through Katana's data mover, kdm.restech.unsw.edu.au, never a login node. From a terminal on your computer, replacing zID with yours:

rsync -av --progress my-dataset/ zID@kdm.restech.unsw.edu.au:/srv/scratch/zID/my-dataset/

On Windows, use WinSCP to the same host and folder, logging in with your zID.

Step 3 · After a run

Find your run

Find the job output

When a job ends, PBS writes its output into your dataset as runs/<job ID>.OU, beside the run directory, runs/<job number>/. When the job succeeds, its output ends with the commands to view and compare it: module load iris, then iris-view with the run directory, and iris-compare. Read it in a terminal in the Virtual Desktop below, for example with tail /srv/scratch/zID/my-dataset/runs/1234567*.OU.

Start a Virtual Desktop

In Katana OnDemand, start a Virtual Desktop with no GPU, 4 cores, 16 GB of memory and 4 hours. That is enough for most volumes, and asking for more only queues you longer. One desktop serves everything below. Open a terminal in it, and run module load iris. That gives the terminal the iris-view and iris-compare commands until you close it, so a new terminal needs it again: without it, the terminal says iris-view: command not found.

Step 4 · After a run

View and compare runs

Both commands run in the Virtual Desktop's terminal, after module load iris.

View a run: iris-view

Run iris-view followed by the run directory, as the job output gives it, such as iris-view /srv/scratch/zID/my-dataset/runs/1234567. napari opens with your volume and the run's label volume over it at half opacity. Scroll through the slices with the slider under the image. Only the slices you look at are read, so even a volume larger than the desktop's memory fits. Close the napari window to quit.

Run iris-view with no run directory to list your 10 most recent finished runs, then type the number beside the one to open.

Compare runs: iris-compare

Run iris-compare. It adds your new runs to your tracking store, /srv/scratch/zID/iris/tracking.db, then opens MLflow in Firefox inside the desktop. On the left, switch from GenAI to Model Training, then click Runs: each run is named after its job ID, under its experiment. Select runs and click Compare to see their settings and per-class Dice and IoU side by side. Leave the terminal open while you use MLflow; Ctrl+C there stops it.

Your tracking store is created the first time you run iris-compare. If it is ever lost, run /srv/scratch/katana_ai/iris/code/bin/iris-rebuild to rebuild it from your run directories. It isn't in the iris module, so type its full path.

Optional

Fiji and ParaView

For a closer look than iris-view gives, open the run's label volume in Fiji, or crop a region of it in Fiji and render it in 3D in ParaView.

Open the label volume in Fiji

  1. In the desktop's terminal, run module load fiji/20240614-2117, then start Fiji with ImageJ-linux64.
  2. Choose File › Import › Bio-Formats, and pick labels.tif in the run directory. In the options, set View stack with to Hyperstack and tick Use virtual stack. Slices are read as you scroll, so stepping through them is slow but works.
  3. The image opens black: classes 1, 2, 3 sit at the bottom of a 0–255 grey scale. Choose Image › Adjust › Brightness/Contrast…, click Set and set the maximum to your number of classes. It stays set as you scroll.

To look around the labels over your volume, iris-view is quicker. Use Fiji to cut out a region for ParaView.

A region in 3D with ParaView

A whole label volume is usually too large to render in 3D in the desktop: once read, the labels take about half the memory of a 16-bit volume. Crop a region in Fiji first.

  1. Import labels.tif with Bio-Formats as above, this time with Use virtual stack unticked and Specify range for each series ticked. Set the T range to the slices you want, such as 600–800: Bio-Formats lists the slices as time points. Only those slices are read.
  2. Draw a rectangle around the region, then choose Image › Crop.
  3. Choose File › Save As › Tiff…, and save it as crop.tif in the run directory. Fiji offers your home folder first. A 200 × 500 × 500 crop is 50 MB.
  4. Close Fiji and anything else you have open: ParaView can hang while Fiji is still running. In a new terminal, run module load paraview/6.0.0, then paraview.
  5. Choose File › Open and pick crop.tif. ParaView asks which reader to use: choose TIFF Series Reader, not GDAL Raster Reader.
  6. In the Properties panel, tick Use Custom Data Spacing and enter the voxel size in the run's dataset.json in all three Custom Data Spacing boxes, so the region isn't squashed. Click Apply. Nothing shows until you do, and then only the region's outline.
  7. To show the boundary between two classes, choose Filters › Common › Contour. It starts with one value, halfway through the labels in your region; set it halfway between the two classes, such as 2.5 between classes 2 and 3, and click Apply.
  8. Or select crop.tif in the Pipeline Browser and set its Representation to Volume. Dragging to rotate stays smooth; after you let go, ParaView takes a few seconds to redraw at full detail.
Optional

Copy a run home

With Globus

Bring a run back with Globus, the same way you sent the dataset. Your computer needs Globus Connect Personal running.

  1. In Katana OnDemand, click Files in the top menu.
  2. Open your run directory, my-dataset/runs/<job number>/, in your scratch.
  3. Click Open in Globus. Globus opens with the run directory on one side.
  4. On the other side, choose your computer and the folder to copy into.
  5. Press Start.

In a terminal instead

Use the same rsync as for staging, with its source and destination swapped, run from your computer. For example, one run directory:

rsync -av --progress zID@kdm.restech.unsw.edu.au:/srv/scratch/zID/my-dataset/runs/1234567/ my-dataset/runs/1234567/

Or use WinSCP to the same host and folder.
