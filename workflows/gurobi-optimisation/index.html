Large-scale Optimisation (Gurobi)

Linear, quadratic and mixed-integer programming for scheduling, logistics, network design and resource allocation. Gurobi handles problems far beyond spreadsheet solvers, and parallelises branch-and-bound across cores.

▶  Run on Katana Opens Katana OnDemand — log in with your zID when prompted.
Version
v12.0.1
Engine
Gurobi
Compute
Katana
CPUs (default)
8

What to expect

  1. Click Run on Katana and log in with your zID.
  2. Point model at your problem file, or supply a Python script building it.
  3. Set the optimality gap and time limit you'll accept.
  4. Choose whether to write the full solution or just the objective.
  5. Set your output directory to your scratch space.
  6. Adjust walltime and resources if needed, then click Submit.

Parameters

ParameterDefaultDescription
model—Model file (.lp or .mps), or a Python script using gurobipy
mip_gap0.0001Relative optimality gap to stop at
time_limit3600Solver time limit in seconds
threads8Solver threads — should match ncpus
outdir—Output directory — use your scratch space
ncpus8Number of CPU cores
mem32gbMemory allocation — branch-and-bound trees can grow large
walltime12:00Maximum walltime (hours:minutes)

Outputs

OutputDescription
solution.solVariable values at the best solution found
summary.jsonObjective value, optimality gap, node count and runtime
gurobi.logFull solver log including the root relaxation
iis.ilpIrreducible infeasible subsystem, if the model is infeasible

Environment

Runs on Katana with module load gurobi/12.0.1. Nothing is installed into your home directory. Gurobi is licensed to UNSW; jobs check out a licence at run time.
