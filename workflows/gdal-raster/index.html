Raster Processing (GDAL)

Batch processing of satellite and aerial imagery — reprojection, mosaicking, clipping, resampling and zonal statistics across large raster archives. The routine geospatial work that becomes impractical on a laptop once the archive passes a few hundred gigabytes.

▶  Run on Katana Opens Katana OnDemand — log in with your zID when prompted.
Version
v3.13.1
Engine
GDAL
Compute
Katana
CPUs (default)
8

What to expect

  1. Click Run on Katana and log in with your zID.
  2. Point input_dir at your raster files.
  3. Set the target coordinate reference system.
  4. Choose the operation — reproject, mosaic, clip or compute statistics.
  5. Set your output directory to your scratch space.
  6. Adjust walltime and resources if needed, then click Submit.

Parameters

ParameterDefaultDescription
input_dir—Directory of input rasters (GeoTIFF, JP2, NetCDF)
operationreprojectOperation — reproject, mosaic, clip, zonal_stats
target_crsEPSG:7855Target CRS — default is GDA2020 / MGA zone 55
resamplingbilinearResampling method — nearest, bilinear, cubic, average
vector_mask—Vector layer to clip or compute zonal statistics against
outdir—Output directory — use your scratch space
ncpus8Number of CPU cores
walltime06:00Maximum walltime (hours:minutes)

Outputs

OutputDescription
*_reprojected.tifRasters in the target CRS
mosaic.tifMerged mosaic, when mosaicking
zonal_stats.csvPer-zone summary statistics
gdal.logFull processing log with per-file timings

Environment

Runs on Katana with module load gdal/3.13.1. Nothing is installed into your home directory.
