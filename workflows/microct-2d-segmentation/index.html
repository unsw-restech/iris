microCT 2D Segmentation (U-Net)

Label a few slices of a microCT volume, and IRIS trains a 2D U-Net on them and segments the whole volume slice by slice. Each run is recorded, so you can compare runs with different settings side by side.

Workflow owner: Patrick Tung

▶  Run on Katana Opens the form in Katana OnDemand. Pick your dataset folder and submit: the other fields have working defaults.
You're ready when
  • Your dataset folder is inside your scratch, /srv/scratch/<zID>
  • Its volume/ folder holds the volume's .nc files
  • train/images/ and train/labels/ hold the same file names
Once per dataset

1 · Stage

Put the volume and your labelled slices in one dataset folder, then send it to your scratch with Globus from your browser.

Staging a dataset

Every run · two clicks

2 · Run

Click Run on Katana, pick the dataset folder and submit. You get an email when the job ends.

Change one setting at a time and keep the experiment name, so the runs compare.

After it finishes

3 · View

In a terminal in a Virtual Desktop, run module load iris, then iris-view to see the labels over your volume and iris-compare to compare your runs.

Viewing and comparing runs

How to lay out and copy your dataset

Lay out the dataset folder and copy it to your scratch as in Staging a dataset. For this workflow:

  • Label 5 to 30 slices. The number of classes is read from your labels, up to 255.
  • Export each training image at the volume's size and bit depth.

Editing the workflow code for one run

The form's script pane holds this workflow's code, run.py, below the comment # Workflow code: edit below. To try a different model architecture, loss, augmentation or training loop, edit it there before you submit: the job runs the code exactly as it appears in the pane. The change belongs to that run alone, which makes it an edited run; the workflow itself is unchanged. Record keeping and reading and writing volumes stay in IRIS, out of the pane, and an edited run uses the same Python packages.

  • Set the fields first and edit the code last. Changing a field after editing rewrites the whole pane and discards your edits. The form warns you first, so you can cancel, but after it refuses to submit that warning no longer appears: your edits are kept, and the next field change discards them without asking.
  • To rerun an edited run, use Load parameters in the form's job history: it restores the fields and your edited code, and the job output says the run is edited.
  • Every run directory keeps the code its run ran as run.py and your changes as run.diff, written before the code starts, so a run that crashes still shows them. The job output prints the diff near the top.
What a run writes and how to view it

Each run writes into your dataset, in runs/<job number>/:

FileWhat it holds
labels.tifThe label volume: one uint8 class number per voxel, the volume's full size, each slice compressed on its own
model.ptThe trained weights
params.jsonEvery form field, and the seed used
metrics.jsonTraining loss and per-class Dice and IoU, per epoch and final
dataset.jsonWhat the run read: folder paths, file counts, the volume's shape, type, voxel size and intensity statistics
run.jsonThe experiment, job ID, how the run ended and whether it is an edited run
commit.txtThe IRIS commit that ran, as the form showed it
run.pyThe workflow code the run ran, as submitted from the form
run.diffYour changes to that code against the commit in commit.txt; empty unless the run is edited

The job output sits beside it, as runs/<job ID>.OU. When the job succeeds, the output ends with the commands to run in a terminal in a Virtual Desktop: module load iris, then iris-view with the run directory, which shows the label volume over your volume in napari, and iris-compare, which opens your runs in MLflow. Fiji and ParaView open the label volume too. The guide covers the Virtual Desktop to start, all four, and copying a run directory home.

To cite a run, use the commit in its commit.txt, as in Cite this workflow.

Something went wrong
  • The form won't submit. Its warning names the rule your dataset folder broke, and your values are kept. Fix the folder and submit again. A stray .DS_Store or Thumbs.db in one of the train/ folders counts as a file-name mismatch: delete it.
  • The job stopped at once with "the IRIS imaging environment is missing". Nothing is wrong with your data. Email patrick.tung@unsw.edu.au with the job ID.
  • The job stopped before training with an ERROR: line about your dataset. It names the file and what's wrong: a training image at a different size or bit depth from the volume, a label slice that doesn't match its image, label values that aren't whole numbers from 0, more than 255 classes, or labels that are all 0.
  • The job ran out of walltime. Submit again with more walltime. Load parameters keeps your other settings.
  • The job ran out of GPU memory. Lower the batch size under advanced options, or the patch size.
  • iris-view says there is no label volume. The run hasn't finished, or it failed: read the end of its runs/<job ID>.OU.
  • The job output doesn't end with the iris-view line. The job stopped at its first error, which is the last thing in the output. The same commands are printed near the start of the output, before training, so the run directory they name may be incomplete.
  • Anything else. Email patrick.tung@unsw.edu.au with the job ID and the end of the job output.
