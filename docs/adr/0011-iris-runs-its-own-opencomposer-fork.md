# IRIS runs its own OpenComposer fork

Supersedes in part ADR-0006: its consequence that OpenComposer regenerates the whole pane when a field the script uses changes, warning first but never merging, and the pane's banner telling researchers to set the fields first and edit the code last. The rest of ADR-0006 holds: the entry script comes from the pane, and the run directory records the `run.py` that ran and its diff.

Until the changeover, IRIS's forms are served by the shared OpenComposer ResTech runs for everyone on Katana OnDemand. The sysadmin's plan for sharing it is one symlink per workflow, so every new workflow would need the sysadmin. IRIS can change neither the app's code nor its look without changing them for every other user, an upgrade made for other users changes IRIS's forms untested, and IRIS's job history shares a `data_dir` with everyone else's. The forms have problems of their own that stock OpenComposer can't fix. Changing a field regenerates the whole pane, so an edit to the workflow code is lost, and silently after a failed `check:`. Nothing stops a researcher editing a line that holds a field, so the form, `check:`, the run record and the submitted script can disagree. The Submit button scrolls out of sight, and text on the Katana OnDemand yellow is hard-coded white (Patrick, 2026-11-06, #159).

- **Own instances.** IRIS gets two OnDemand system apps of its own. The **IRIS instance**, `OpenComposer-iris`, shown as "IRIS OpenComposer" under **Jobs**, serves the system clone's `workflows/` to researchers. The **test instance**, `OpenComposer-iris-test`, shown as "IRIS OpenComposer (test)", serves each user's own `<%= ENV['HOME'] %>/iris/workflows` and runs its forms as that user, so a workflow author proves a workflow on the same code researchers get (Patrick, 2026-11-11). Each is its own checkout of the fork in `katana_ai`'s scratch, beside the system clone, since an app's name comes from its `manifest.yml` and its settings from its `conf.yml.erb`, and the sysadmin makes one symlink to each, once (#172). Each has its own `data_dir`, since OpenComposer 2.0 migrates its history from PStore to SQLite and would otherwise rewrite the shared 1.9.0 OpenComposer's history in `~/composer`. The shared OpenComposer stays on stock upstream for everyone else.
- **The fork.** The code is `unsw-restech/OpenComposer`, a fork of upstream based on v2.0.2. Upstream release tags are merged on purpose, once the fork's browser tests pass, and the fork never tracks upstream `main`. Its code stays generic: the platform name, shown in the navbar and the tab title (`<form> | IRIS`), and the link back to the catalogue are config keys, and IRIS uses no logo, so another ResTech platform could install the same fork as `OpenComposer-<platform>`. Patrick's dev install and both instances run one pinned fork commit, deployed like the system clone: a listing of the commits a move deploys, Patrick's go-ahead quoting them, then the pinned commit (#162).
- **Field-owned lines.** Changing a field rewrites only the lines that hold it (feature 1 of upstream PR #37), so an edit anywhere else survives. `overwrite_warning` and the "Discard and continue" modal go, and the duplication upstream found when a checkbox is ticked is fixed (#165).
- **Locking.** Lines holding a field are locked: shaded and not editable, "Set by *<field label>*" on hover, and a click focuses the field. A researcher changes a value only through its field, so the form, `check:`, the run record (`--field …`) and the submitted script always agree (#168).
- **The editable region.** A form may name two marker lines of its script, and every line outside them is locked, with "Fixed by the form" on hover. Each imaging form marks its `run.py` heredoc, so the workflow code is the only thing a researcher edits, and `bin/check` fails an imaging form that declares no region (#161, #171). ADR-0006's banner becomes a one-line hint, "Edit the workflow code below".
- **A sticky Submit bar.** One Submit bar stays on screen while the form scrolls (#166).
- **Text follows contrast.** Navbar, footer and description text is black or white by its background's brightness, so text on the Katana yellow is black (#164).

## Considered Options

- **Sysadmin symlinks into the shared `apps_dir`** (the sysadmin's plan): no fork to keep, but every new workflow needs the sysadmin, IRIS changes neither code nor look, the sysadmin's upgrades reach IRIS's forms untested and the job history stays shared.
- **Stock upstream on IRIS's own instance**: settles the sharing problems, but none of the form's: an edit still goes when a field changes, field lines stay editable and Submit still scrolls away.
- **Reverse-updating fields** (feature 2 of upstream PR #37), where editing a field's line in the script updates the field: rejected, since lines such as `#{time_1}:#{zeropadding(time_2, 2)}`, `"#{:experiment}"` and lines holding several fields can't always be converted back to a value. Locking keeps the form and the script in agreement without guessing.

## Consequences

- IRIS keeps a fork. Each upstream release is merged by hand after the browser tests pass. The field-rewrite change and the contrast rule are offered upstream (#169), so IRIS carries less of its own code over time; the rest stays fork-only unless upstream asks.
- The sysadmin is needed once, for the two symlinks. After that, updating the fork, adding a workflow or changing a form needs nothing from them.
- Until the changeover (#173), the shared OpenComposer keeps serving IRIS's `workflows/`, and the Run buttons and docs point at it. A real job from the IRIS instance comes first, then one commit moves every Run button and doc to `/pun/sys/OpenComposer-iris/<slug>` and turns the banner into the hint. The sysadmin repoints the shared `apps_dir` only after that.
- The test instance finds an author's forms only in a clone at exactly `~/iris`.
- The form test helper renders as the pinned fork commit does, not as 1.9.0 does (#167).
- An edited run can differ from its commit only in `run.py`, so the `run.py` and `run.diff` it keeps (ADR-0006) are everything the researcher changed.
